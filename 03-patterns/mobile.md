# 移动端适配（BFS 4.1.2）

> BFS 的官方拒审标准是行为结果，不是固定 breakpoint、边距或触控尺寸。ISO 使用一组保守视口和可访问性基线扩大测试覆盖。

## BFS 三条硬判据

1. 移动设备上整页需要横向滚动。
2. 部分内容完全不可访问，例如折叠后无法展开，或不换行且没有局部横滚机制。
3. 内容被不合理压缩，例如桌面双列在移动端仍保持双列而不堆叠。

表格、图表等宽内容可以在自身容器内局部横滚；不能让整个页面横滚，也不能把被遮挡内容留在没有访问机制的区域。

## ISO 保守测试基线

以下用于提前发现问题，不是 Shopify 公布的 BFS 数值阈值：

- 在 `375 / 390 / 412 / 768px` 等视口逐页测试。
- 自定义布局以 16px 作为窄屏边距起点；官方 `s-*` 布局优先使用语义值。
- 自定义交互目标以 `44 x 44px` 作为团队可用性基线；官方组件使用其内建触控尺寸。
- 正文和交互文字遵守当前 Visual design 的最小字号指导；不要用缩小文字解决空间问题。

## 实现方式

```html
<s-grid gridTemplateColumns="repeat(auto-fit, minmax(min(100%, 16rem), 1fr))" gap="base">
  <!-- responsive content -->
</s-grid>
```

- 优先使用当前 `s-page`、`s-grid`、`s-stack`、`s-box` 的语义布局。
- 多列在空间不足时堆叠；不能用固定宽度维持桌面列数。
- 表格/图表在局部容器中滚动或转换为移动列表模式。
- 按钮本身没有 `fullWidth` 属性；需要占据一列时由父布局定义列宽，不伪造组件 API。
- 内容通过换行、展开、局部滚动或移动替代布局保持可访问。

## 验收

1. 用 `shopify app dev` 在桌面 Admin 逐页验证正常、空、加载和错误状态。
2. 使用 DevTools 覆盖 ISO 视口，检查 `documentElement.scrollWidth <= clientWidth`。
3. 在 Shopify mobile 真机打开 App，验证滚动、输入、键盘、浮层和导航。
4. 对表格/图表确认只有局部容器横滚，隐藏内容均有可操作的访问机制。
5. 确认两列/多列在窄屏合理堆叠，文字和按钮没有被挤压或遮挡。

## 常见失败

- 固定宽容器或绝对定位元素撑破视口。
- 桌面列数在手机上不变。
- 内容被 `overflow:hidden`、截断或折叠，却没有展开/滚动机制。
- 把表格直接撑到页面宽度之外，而不是建立局部滚动区。
- 通过缩小字号或点击区硬塞内容。
