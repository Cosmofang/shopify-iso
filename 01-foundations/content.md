# 内容 Content

> 官方 Content 指南负责产品文案的可读性、一致性和行动导向；BFS 4.2.1 将醒目的拼写、语法、难懂文案和缺少上下文列为拒审理由。

## Plain language

- 使用标题、列表和短句，让商家快速扫描。
- 以美国 7 年级阅读水平作为英文文案基准，不是机械评分门槛。
- 避免行业黑话、过度技术语言、习语、反讽和大段文字，减少翻译与理解偏差。
- 单位、日期、输入格式和动作结果必须有足够上下文；不要只写 `Time`、`Value`、`Invalid`。

## Consistency

- 同一个对象、动作或概念始终使用同一个名词、动词或短语，不轮换同义词。
- Navigation、页面标题、字段、按钮和反馈文案使用同一术语表。
- 不重复 App header 已显示的页面标题，不在 body 复制 App nav，也不在同页用多种方式重复同一内容。

## Encourage action

- CTA 以强动词开头，使用主动语态；页面操作推荐“动词 + 名词”，结果清晰、可预测。
- 把最重要的信息和任务放在前面；复杂任务拆成聚焦单一动作的步骤。
- 给商家足够信息自行决定，不使用命令式、施压、羞辱或效果承诺。

## App 自称

同一内容区第一次提到 App 或公司时使用正式名称；后续引用可使用 `we`，兼顾清晰和简洁。

## BFS 验收

- 标题、navigation item 和 CTA 没有醒目的拼写或语法错误，即使商家能猜出含义也不能放行。
- 标签、单位、时间范围和操作结果有充分上下文。
- Onboarding、错误信息、促销和计划限制还需分别通过 4.2.2、4.2.4、4.3.1-4.3.7。

## ISO 文案检查

- [ ] 核心术语只有一种写法，页面间一致
- [ ] 句子短、主动、无黑话/习语，大段文字已拆分
- [ ] CTA 以动作开头并能预测结果
- [ ] 页面标题 / App nav / body 没有重复结构
- [ ] App 首次自称使用正式名，后续 `we` 不造成歧义
