# 体验模式

Polaris React 的 Pattern 文档保存了常见商家任务的设计理由，但页面本身已经是历史来源。新 App 必须先选择当前 [App Home Patterns](https://shopify.dev/docs/api/app-home/patterns) 的 Homepage、Index、Details、Settings 与 Compositions，再用本章校验信息结构和行为。

## Pattern 不是组件拼装示例

Pattern 描述的是可重复的商家目标、信息层级和动作位置。历史示例里的 `Page`、`Card`、`IndexTable`、`Popover` props 不能直接翻译成同名 `s-*` 属性；先保留任务关系，再查当前组件合同。

## Resource index

资源索引用于查找、比较、筛选、选择和批量管理同类对象。

### 结构

1. 页面标题使用资源类型复数，并提供影响整个索引的动作。
2. 创建资源通常是右上方主动作；没有创建能力就不显示空按钮。
3. 搜索、筛选、排序、保存视图和多选动作位于数据上方。
4. 主体给每个资源稳定的识别字段、状态和关键比较值。
5. 行进入资源详情；批量动作只作用于已选集合。

### 验收

- 数据列回答商家真正需要比较的问题，不照搬数据库字段。
- 搜索、筛选和排序状态可恢复、可清除，并与结果数量一致。
- 空集合、无搜索结果、权限不足、部分加载和失败是不同状态。
- 窄屏不能简单压缩桌面表格；优先保留识别、状态和主动作。
- 批量动作在选择发生后出现，不造成页面跳动或误解作用范围。

当前实现优先使用 App Home Index template/composition 和当前表格能力，不复制旧 `IndexFilters` 示例。

## Resource details

资源详情与资源索引成对：索引用于发现和比较，详情用于查看、创建和编辑一个对象。

- 页面头部承载返回索引、对象名称、全页动作和相邻对象导航。
- 主要内容放定义对象的字段和核心任务；状态、元数据、摘要等支持信息放次要区域。
- 相似信息放在同一 section，按重要性排序。
- 新建与编辑尽量保持相同心智模型，减少商家重复学习。
- 对象特有动作排在通用 archive/delete 等动作之前，破坏性动作单独分组。
- 移动端按任务顺序堆叠，不能只按桌面左右列的 DOM 顺序碰运气。

历史两栏 `2fr/1fr` 和默认页面宽度只表达“主次关系”，不是当前固定 CSS。

## App settings

设置页面的目标是先找到设置，再安全地修改设置。

- 每组左侧或上方使用可扫描标题和必要说明，右侧或下方放实际控件。
- 同一业务结果的设置放在一起，不按技术服务或数据库表分组。
- 所有设置组按单一纵向顺序出现；窄屏变为标题在前、控件在后。
- 说明只在帮助理解作用、后果或依赖时出现。
- 修改后有明确未保存、保存中、保存成功、失败和离开确认状态。
- 会影响费用、权限、商店前台或数据的设置，在操作前说明范围和后果。

当前 Settings template 与 contextual save bar 优先于旧两栏 React 代码。

## Card layout

历史 Card pattern 的价值在于职责分区，而不是鼓励每段内容都变成卡片。

### Header

- 标题代表整张卡的目的；列表卡可用对象类型作为标题。
- Header action 必须影响整张卡，例如编辑或查看来源。
- 只影响某一行或 section 的动作贴近对应内容。
- 主流程 CTA 不放 header，通常在 footer 或页面级动作区。
- 图标动作只有在含义熟悉时使用，并提供 tooltip 和可访问名称。

### Body

- 一个 section 代表一个相干子任务；单 section 通常不再重复 section 标题。
- 不用 section 包装每个列表项。
- 表单字段宽度与输入长度匹配，避免短值占满整行。
- 长列表提供展开、分页或进入完整列表的路径，不能无限拉长卡片。

### Footer

- Footer 放阅读内容后自然发生的下一步 CTA。
- 默认使用普通强度动作；只有全页最重要的动作才用 primary。
- 超过两个 CTA 时重新评估层级，必要时收进 action list。
- 列表的添加、展开和折叠动作放在列表结束位置，标签利用卡片上下文避免重复对象名。

### Spacing

- padding 表达容器边界，gap 表达元素之间的关系；两者不能互相代替。
- 更深层的可见容器通常使用更小 padding，防止嵌套越来越膨胀。
- 同组内容用紧间距，不同 section 用较松间距；标题必须明显属于后续内容。
- 历史 `space-100` 至 `space-400` 是旧 token 语义，当前实现读取当前组件/token，不复制数值。
- 优先光学对齐，避免 icon、button 或带边界元素看起来错位。

## Common actions

### Add

`Add` 把新对象或已有对象加入当前上下文。短列表放在列表末尾，长列表或表格放在 header；创建资源通常是页面主动作。不要为了收集本应在新建页完成的设置，先弹一个中间 modal。

### Copy

文本使用复制图标，URL 可使用链接图标；点击后立即给行内确认。动作位于菜单中时可以用简短 toast 确认。复制失败必须给恢复信息。

### Delete 与 Remove

- `Delete` 销毁对象或数据，通常不可逆，使用 destructive 语义和 delete icon。
- `Remove` 只解除当前关系，对象仍存在，常用 `x` 或明确的 Remove 标签。
- 不混用两者，否则商家无法判断数据是否仍可恢复。
- Delete 放在 action list 底部并与普通动作分组；不要让页面充满 critical 按钮。
- 批量删除明确数量、对象类型、不可逆范围和完成结果。

### Edit、More、Pin

- Edit 修改现有对象，动作靠近它所控制的内容。
- More actions 只收纳次要且相关的动作，不用来掩盖信息架构问题。
- Pin 把对象放到更易访问位置；pinned 状态可见、同组展示并容易取消。

### 交互与平台

- 相同外观必须有相同行为。
- 键盘输入显示清晰 focus，不能依靠颜色单独表示可交互。
- Hover 可在桌面披露次要动作，但移动端必须有可触达的等价入口。
- Touch target、动作间距和危险操作确认按真实设备验证。

## Date picking

### Single date

适用于生日、预计到达日或某天发生的事件。提供可输入字段与日历；字段标签说明业务含义，例如 Start date。选择即可完成时可以自动关闭，但必须保持键盘和错误恢复可用。

### Preset date list

当常见日期可以预测且不需要任意日期时，直接给 Today、Yesterday、Last 7 days 等列表。默认项选择大多数商家最常用的范围，单日排在范围之前，范围由小到大。

### Date range

适用于分析趋势或跨多日事件。预设列表、文本输入和日历分别服务快速选择、长跨度输入和视觉选择；因为包含多步，使用明确 Apply/Cancel。禁用日期必须可感知，非法日期恢复到上一次有效值并给字段错误。

所有日期显示、解析、周起始日、时区和范围边界按商家 locale 与业务规则实现；历史 `YYYY-MM-DD` 示例不是全球显示格式。

## Pickers

Picker 的复杂度随选项规模和任务增加：

- 只有 1 个有效选项：直接显示结果，不展示无意义 picker。
- 少量选项：完整展示，不增加搜索和排序。
- 大量选项：增加搜索、排序、最近使用和分页/增量加载。
- 导航或过滤可固定主要选项；表单选择可固定最近或高频选项。
- 排序依据对象本身：名称适合字母序，最近编辑适合工作集合，日期按时间序。
- 主任务中的 picker 可直接嵌入；次要选择可渐进披露到 popover 或当前官方 resource picker。

历史 `2-10`、`11+` 等阈值来自特定 location/segment 案例，不是所有 picker 的硬规则。当前 Shopify 资源选择优先使用官方 picker API，不重建大型资源浏览器。

## Text fields

- Label 通常使用简短名词；独立字段缺少上下文时可以用动作短语。
- Placeholder 不能代替 label 或持久帮助，它会在输入时消失并可能低对比。
- Help text 只补充格式、用途、可见对象或查找位置，不重复 label。
- 有固定格式的 modeled input 给具体示例；自由文本不编造示例内容。
- 多行备注说明谁能看到，避免商家误把内部备注发给客户。
- 搜索等熟悉场景可使用 placeholder，但仍需要可访问名称和清晰 focus 行为。

## Loading

### Make it fast

缓存重复数据、在明确意图时预取、优先首屏数据，并限制初次页面内容。性能优化必须以真实任务为单位，而不是只优化单个请求。

### Make good use of time

- 尽快进入目标页面上下文，不在旧页面等待全部数据。
- Skeleton 的结构和断点必须接近最终内容，避免建立错误预期。
- 能立即显示的标题、section label、图标和稳定动作直接显示，不用 skeleton 替代真实内容。
- 未依赖加载数据的控件保持可用；只有确实不能执行时才禁用。

### Focus on the job

- 用户动作约 100 ms 内有明确反馈。
- 能展示真实进度就不用无限 spinner。
- 保持布局稳定，避免加载完成后按钮、行和内容突然位移。
- Spinner 表示局部未知等待，不作为整页空白占位。
- 超过约 10 秒的任务说明预计时间、后台执行方式、可离开性和完成通知。

当前性能与 BFS 证据见 [05-engineering/performance.md](../05-engineering/performance.md)。

## New feature awareness

只有同时满足以下条件才考虑打断商家：功能具有高业务价值、给商家带来明显新价值、值得从当前任务中分散注意力。一般改进、重命名或已有能力的新入口不满足条件。

- 不在每个 section 堆 New badge 或 pip。
- Pip 表示列表中的未读/新状态，不表示新功能。
- 历史建议在点击、首次看到 5 天或 3 次 session 后移除；当前实现应采用有记录的到期策略，而不是永久标签。
- 对第三方 App，BFS 的“不分散商家注意力”规则优先，不能照搬 Shopify 内部推广特例。
